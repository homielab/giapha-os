# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- The Docker image is now based on `oven/bun:1-alpine` (smaller image).

### Fixed

- A locked account that signs in again no longer sends administrators a new approval email, and locking an account while its approval page is open (even as "Confirm approval" is pressed) keeps it locked; approval now runs in one database transaction. Needs the migration `20261031180000_lock_blocks_approval.sql`.
- Running the `/setup` SQL bundle again on a database that already has the security hardening migration (20260901) no longer fails with "function already exists in schema private"; the README's re-run guidance is now accurate.
- Quick search (⌘K) finds a spouse or children right after they are added, and logging out clears it, so the next account on the same browser no longer sees the previous tree's names.
- Large trees: the in-law list of a member with hundreds of children and the parent/child loop check no longer miss rows past 1000; a self-hosted server with `max_rows` below 1000 no longer cuts lists at the first page.
- Restoring a backup larger than 4.5 MB on Vercel now explains the host limit instead of failing with a bare 413.
- Member form: a lunar death date with day 31, month 13, or day 30 of a 29-day month is now refused ("invalid death date") instead of being saved with no death anniversary ever shown.
- Names are saved in one Unicode form (NFC) with single spaces, and a note of only spaces or blank lines is no longer saved.
- Statistics: the gender bar and legend now include Other, so the parts add up to the total; ages use today's date in Vietnam time.
- Locking a user in Manage users now revokes their emailed approval link: the old link (valid 7 days) shows "Request revoked" (HTTP 410) instead of turning the account back on. Needs the migration `20261031120000_revoke_approval_link_on_lock.sql`.
- Kinship finder: the wife of a grandfather (or of an older ancestor) who is not recorded as the mother of his child on the line, when that child has only one parent recorded, is now "Bà nội" / "Cụ bà" with a note that she may be a later wife and a link to the child's profile to add the parent, instead of "Wife of Ông nội".
- Docker: `robots.txt`, `sitemap.xml` and the web manifest now use `SITE_NAME` / `APP_URL` set when the container starts, instead of `localhost` and the default name baked in at build time.
- Gallery images no longer break in a tab left open over an hour: the page fetches fresh image links before they expire or when an image fails to load.
- README: the Member role can also add, edit and delete the custom events they created.

### Added

- Data check lists children with only one parent recorded whose parent has a spouse, naming the spouses as the possible missing parent (a hint only; nothing is linked).
- Calendar export (.ics) adds a reminder at 8 AM 1, 3 or 7 days before each event (default 1 day, "No reminder" to turn off); the choice is remembered in the browser.
- Import can add a file to the current tree instead of replacing it: choose "Add to the current tree" after picking a JSON backup, GEDCOM or CSV ZIP (e.g. a relative's branch). Members and events get new ids and are inserted in one transaction without touching existing data; photos are not imported. A "Scan for duplicates now" button then helps merge people who are in both. Needs the migration `20261030180000_add_append_import.sql`.

- Data check and the add-relationship form now flag a marriage between a parent and child, between siblings (sharing a biological parent), or with someone who died before the other was born; the form asks before saving it.
- Kinship finder: spouses of grandparents' siblings and of parents' cousins get their own terms ("Bà Mợ", "Ông Dượng", "Ông Bác" / "Bà Bác", "Mợ họ", "Dượng họ", "Bác gái họ") instead of "Wife of Ông Cậu"; grandchildren and great-grandchildren of a grandparent's sibling are "Cháu", no longer "Chắt" / "Chít".
- Kinship finder: children of two remarried parents (no parent in common) are now "Anh kế" / "Chị kế" / "Em kế" by birth year, and two wives of one husband (or two husbands of one wife) get a description naming that spouse, instead of "Unknown".
- The calendar file (.ics) now holds death anniversaries and lunar events for this year and the next four instead of two; the file name, each event's description and a caption under the export button say until which year it reminds.
- Kinship finder: the parents of a married couple are now "Ông thông gia" / "Bà thông gia" (sui gia) to each other, with the path through their children, instead of "Unknown".
- The gallery photo viewer has Previous/Next buttons, Left/Right arrow keys and an "Image 3 of 12" counter, following the order on screen; deleting a photo moves on to the next one.
- Data check now lists three mistakes common after a GEDCOM/CSV import: people with no parent, spouse or child at all, a biological child whose generation is not the parent's plus one (in-laws and adopted children skipped), and children of one father or mother who share a birth order or whose birth order runs against their known birth dates.
- The member list search finds people by birth or death year (e.g. `1950`); every name word must match the full name or the other names, so `an binh` no longer matches An whose other name is Bình.
- The statistics page has a Lifespan card: average lifespan, the longest-lived person and the oldest living member (linked to their profiles), and average lifespan by birth decade. Only people with both a birth and a death year are counted, and the card says how many.
- A "View on tree" button on the member page and in the member details dialog, for every role, opens the family tree with that person as the root, so a branch can be seen without going back to the list and picking the root by hand.
- Upcoming event cards on the dashboard are now links: a birthday or death anniversary opens that person's profile, a custom event opens the events page. They can be reached and opened with the keyboard.
- Data check now lists people older than 120: living with no date of death at all (common in old GEDCOM/CSV trees, where they still got a birthday every year and counted as living) or with more than 120 years between birth and death year.
- Data check now lists people who have a date of death (solar or lunar) but are not marked deceased, which a CSV/JSON restore can leave behind: such a person had no death anniversary and counted as living in the statistics.
- Data check now also lists a father who died more than 10 months before the child's birth (more than a year when a month or day is missing), a common entry mistake after a GEDCOM/CSV import, like the mother rule the member form already had; adopted children are skipped.
- Data check now lists parent–child loops (someone who ends up as their own ancestor, common after a GEDCOM/CSV import), naming each person on the loop with a link to their profile, and people with a marriage or parent–child link to themselves.
- GEDCOM import keeps the place of birth (`BIRT`/`PLAC`), the place of death (`DEAT`/`PLAC`) and occupations (`OCCU`) from Gramps, MyHeritage and other programs as "Nơi sinh: …", "Nơi mất: …" and "Nghề nghiệp: …" lines at the end of the person's note, instead of dropping them. Exporting and importing again does not repeat the lines.
- GEDCOM import keeps cited sources: a `SOUR @S1@` citation of a person or a family becomes a "Nguồn: <title>" line in the person's or marriage's note. The restore confirmation now warns how many source/repository records the file has and how many note pointers lead to notes missing from the file, instead of dropping them silently.

- The burial place can be entered for a deceased member (under the dates of death in the member form) and shows on the member page, the printed profile and the family book ("An táng tại …"). GEDCOM export writes it as `BURI`/`PLAC` and import reads it back.
- Members can store a burial place ("Nơi an táng"), public like the dates of death, so the family knows where to go for tomb sweeping. JSON (now format v5) and CSV backups carry it, older backups restore it empty, and merging duplicates fills an empty burial place from the merged-away profile. Existing installs need the new `add_burial_place` migration (Dashboard → Upgrade).
- Custom events can repeat every year: a "Repeats" choice in the event dialog offers once, every year on the solar date, or every year on the lunar date (like a death anniversary, leap month kept), so clan meetings or tomb sweeping no longer need to be entered again each year. Backups (JSON/CSV) and the .ics export carry the choice; existing installs need the new `custom_events_recurrence` migration (Dashboard → Upgrade), existing events stay one-off.
- GEDCOM import now reads files saved as UTF-16 or UTF-8 with a BOM and legacy ANSI (windows-1252) files from Family Tree Maker, Legacy and similar programs, using the header's `CHAR` line. ANSEL files and files with unreadable characters show a warning in the restore confirmation before anything is replaced.
- GEDCOM export now writes generation, birth order and the in-law flag as custom `_GEN`, `_ORDER` and `_INLAW` tags (only when set) and import reads them back, so moving a tree between two installs no longer loses the order of children or the in-law flag. Other programs ignore the tags; files without them import as before.
- Members list: the filter now also offers "Living", "Missing birth year" and one "Generation N" entry per generation in the data, next to the existing ones. Changing the filter returns to the first batch.
- SEO: the home page carries `WebSite` and the about page `SoftwareApplication` structured data (JSON-LD) so search engines recognise the app as open source family-tree software. Site-level only: no member data, and none on dashboard pages.
- Contributor and security docs: `CONTRIBUTING.md`, `SECURITY.md` (private vulnerability reporting, never share the service-role key), bug and feature issue forms and a pull request template, linked from both READMEs.
- Dashboard → Lineage: a "Family book" renders the whole tree as a printable book, generation by generation. A cover shows the most common surname, the print date and a table of contents; each generation starts on its own page and numbers its members. Every member lists other names, solar birth and death dates, the lunar death date, parents, spouses (in-law marked), children in birth order with links to their entries and the note; members without a generation get their own section at the end. Printing is black on white without the app header or footer, like the member profile.
- Dashboard → Backup & Restore: a "Data check" tool scans the whole tree for impossible dates and repeated links, common in GEDCOM/CSV imports: death before birth, a child born after the mother died, a parent less than 12 or more than 70 years older than the child (adopted children skipped), birth or death dates in the future, and repeated marriage or parent–child links. Findings are grouped by kind with a link to each profile, including a "Missing info" group (no birth year, deceased but no death year, gender unknown) to know what to ask the elders; view only, nothing is changed. Admins only; no migration.
- Dashboard → Backup & Restore: the "Possible duplicates" tool can merge two duplicate profiles into one. A dialog picks the keeper, previews everything that moves over (relationships re-pointed or removed as duplicates, private details and empty fields filled from the merged-away profile, other names remembered, notes appended), recommends downloading a backup first, and merges in one database transaction after typing the deleted profile's name — nothing is left half-merged when an error occurs. When the kept profile already has its own photo, the merged-away profile's photo file is deleted too, so no unused private photo stays in storage. Needs the new `merge_persons` migration on existing installs (Dashboard → Upgrade); admins only.
- Dashboard → Backup & Restore: a "Possible duplicates" tool scans the whole tree, including data imported from GEDCOM or CSV, and lists members who may be the same person (same name ignoring accents plus the same birth year, or the same name and a shared parent) with a link to each profile. View only; nothing is changed.
- Docker: the image has a `HEALTHCHECK` on the `/login` page, so `docker ps` shows `healthy`/`unhealthy`. The English README now also documents the `update_generations` migration.
- Member page: a "Print profile" button prints the profile on A4 without the header, footer and edit buttons, in black on white, with the photo, the full note and the family list; the page title is the name with birth and death years.
- Dashboard: a search button in the header (also Ctrl/⌘ + K on any dashboard page) finds a member by name without accents ("nguyen van" finds "Nguyễn Văn …"), shows birth/death years to tell namesakes apart, and Enter opens the profile. The list loads only when the search is first opened.
- Member form: a "Leap month" checkbox next to the lunar death date, shown when that lunar year has the typed leap month (e.g. 2023 month 2, 2025 month 6), so a death date in a leap month can be entered from the lunar date alone.
- Keyboard access to the tree views: in the Bubble view every family can be reached with Tab (read out with the names and birth years) and selected with Enter or Space; on the Tree, `+`/`-` zoom around the centre, `0` resets and the arrow keys scroll by 40 px. Both canvases announce how to use them.
- Events page: an "Add to calendar (.ics)" button downloads birthdays (repeating yearly), death anniversaries for this and next year (lunar dates, same solar dates as the page) and custom events, ready to import into Google or Apple Calendar for reminders. The README feature lists (Vietnamese and English) now cover the bubble view, A4/A3 PDF, pinch zoom, duplicate checks, custom events, the lunar recompute tool and the English interface.
- Members list view: shows the first 60 members and a "Show 60 more" button instead of rendering everyone at once; a new search, filter or sort starts again from the first 60. Tree, mind map and bubble views are unchanged.
- Restore: the file is read as soon as you choose it. A broken or invalid file shows its error right away, and the confirmation now says how many members, relationships and events the file holds (and its export date), with a "Download the current backup first" button before anything is deleted.
- A translated (Vietnamese/English) "page not found" page, for example for a wrong member link, and a fallback error page; every dashboard page now has its own browser tab title (the member's name on a member page).
- GEDCOM export writes other names (`NAME` with `TYPE aka`) and the lunar death date as a custom `_LUNAR` tag under `DEAT`; import reads them back, so an export followed by an import keeps both.
- Export: besides the single-page PDF, the menu now offers multi-page A4 and A3 landscape PDFs. The tree is cut into sheets with a 10 mm overlap for gluing and a "row,column / rows x columns" label on every page; the last choice is remembered.

The member list loads once when the form opens and is filtered in the browser, showing up to 20 matches (names starting with what you typed first); a failed load now shows an error. ### Changed

- Profile photos on the members (tree, list, mind map, bubbles), kinship and member pages keep the same link between page loads for 12 hours (signed links now last 24 hours instead of 1), so the browser shows them from its cache instead of downloading hundreds of photos again on every visit. A changed photo gets a new link right away.
- Member list: "Given name (A-Z)" sorts by the given name (last word) first, then the whole name, so a one-surname family no longer sorts by middle name; search results with equal rank follow the same order.
- The gallery remembers the Timeline/Grid choice across pages and visits.
- Expanding or collapsing a branch, filtering or resizing the window on a large family tree is smoother: lining up the card heights of each generation now makes the browser lay out the page once instead of once per generation (20 times on a 20-generation tree).
- Large family trees (more than 1,000 members or relationships) open faster on the members list, tree, kinship, statistics, events and lineage pages, and back up faster: after the first 1,000 rows, the remaining rows are loaded four pages at a time instead of one after another. Trees under 1,000 rows load as before.
- Pages load less JavaScript up front: the animation library's features now arrive after the first render instead of with every page. First load JS (gzip) drops by about 27 kB: home 226 → 198 kB, login 297 → 269 kB, members 347 → 320 kB.
- Updated Next.js and eslint-config-next to 16.4.3, lucide-react to 1.63 and @types/node to 26.6.6.
- A member page loads the person from the database once instead of twice (the page title and the page share one query).
- Opening a member's relationships is faster: the children's marriages and the grandchildren counts are fetched at the same time instead of one after the other, grandchildren are counted without downloading the rows, and relatives are loaded without their notes.
- Dashboard and login pages make fewer Supabase queries: the check that the database is set up now runs only until it first succeeds (a fresh install still goes to `/setup`), and a dashboard page reads the signed-in user's profile once instead of twice.
- Exporting a branch is now covered by tests and walks the tree without recursion, so very deep or cyclic data cannot overflow or hang it; the README states what a branch export includes (descendants incl. adopted, their spouses; custom events are always exported in full).
- Gallery uploads are scaled down in the browser to at most 2048 px on the long side and stored as WebP (quality 0.85), so a 6 MB phone photo takes well under 1 MB and the gallery page loads much faster on mobile data. GIFs, animated WebP and images that are already small are uploaded unchanged; photos uploaded earlier are not touched. The 10 MB limit still applies to the file you pick.
- Internal: the death-date input logic of the member form (solar/lunar sync and the leap-month flag) is now plain functions in `utils/deathDates.ts` with tests; behaviour is unchanged.
- Backup and restore: the export card and documentation now explain that JSON, CSV, and GEDCOM backups do not include photos or the `gallery_items` table, and that Supabase Storage buckets `avatars` and `gallery` must be copied separately when moving to a new install.
- Data page: if the member list for choosing an export root fails to load, an error is shown instead of a silently incomplete list.
- CI: every push and pull request now also runs `bun run build` and a Docker image build (not pushed), so a broken build no longer slips through.
- Pages no longer download both languages: the server passes only the current language's strings to the browser, removing a 110 KB (34 KB gzip) script from every page; all client scripts together go from 2,777 KB to 2,668 KB (821 KB to 790 KB gzip) in `bun run build`. Switching between Vietnamese and English works as before.
- Events page and dashboard: only members who have a birthday or a death date (solar or lunar day and month) are loaded, and without their photo link, so large trees send far less data. The events shown are the same.
- Lint now fails on any warning (`--max-warnings 0`, also in CI); unused imports and variables across the components were removed, no behaviour change.
- Internal: GEDCOM import (`parseGedcom`) is split into `utils/gedcom/persons.ts` (`readPerson`), `families.ts` (`readFamilies`) and `relationships.ts` (`dedupeRelationships`), with a shared NOTE reader in `notes.ts`; `import.ts` only orchestrates. Imported data is unchanged.
- Internal: relationship mutation logic in `utils/relationshipMutations.ts` is split into `utils/relationships/` (`add`, `bulkChildren`, `spouse`, `shared`; each file under 200 lines) with a barrel re-export. Imports and tests are unchanged.
- Internal: GEDCOM import/export in `utils/gedcom.ts` is split into `utils/gedcom/` (`types`, `dates`, `names`, `export`, `import`; each file under 250 lines). Imports from `@/utils/gedcom` and the exported files are unchanged.
- Internal: the relationship (kinship) logic in `utils/kinshipHelpers.ts` is split into `utils/kinship/` (`types`, `terms`, `graph`, `blood`, `resolve`), with the in-law terms in lookup tables instead of text checks. The terms shown are unchanged; the common-ancestor, deep-generation and in-law cases have more tests.
- Kinship page: the note about ambiguous terms is now decided by the calculation itself instead of searching the text of the answer, so it also appears for the generic "Họ hàng" result.
- Members and lineage pages load only the relationship columns they use (no note or timestamps): for 2,000 people with about 4,800 relationship links the data sent with the page drops from about 1,310 KB to about 810 KB. The language dictionaries were already not part of the page data (only the chosen language code is sent).
- The members and lineage pages no longer load `note`, `created_at` and `updated_at` of every person, which no view reads: about 24% less data for 2,000 members (≈ 983 KB → 743 KB in a synthetic test).
- The gallery signs all image links of a page in one storage request instead of one request per image.
- Profile photos on the members page (tree, list, mindmap, bubble view) and the kinship page load from links signed in one storage request for the whole page, instead of one request through the app server per member. On a member's page the photos of the relatives (parents, spouses, children, children-in-law) are signed the same way, in one request. Other pages still load them through `/api/avatar`.
- The statistics page (`/dashboard/stats`) computes the totals on the server from the few columns it needs and sends only the numbers to the browser: for a family of 2,000 members the page data drops from about 2 MB to about 1 KB.
- The PDF/image export libraries (jspdf, html-to-image) load only when you export: opening the tree or mindmap view downloads 25 KB instead of 446 KB of JavaScript (7 KB instead of 143 KB gzipped). d3 is replaced by the d3 modules the bubble view uses (`d3-selection`, `d3-zoom`, `d3-force`, `d3-drag`, `d3-transition`).
- Updating generations (Lineage page "Apply", or saving a member with "update descendants' generations") saves all members in one call to the new `update_generations` database function (migration `20261026120000_add_update_generations.sql`) instead of one request per member. It runs in one transaction: if any member fails, nothing changes and the Lineage page shows the error instead of "applied". Databases without the migration keep the per-member update, now report failed rows, and show a reminder to upgrade on `/dashboard/upgrade`.
- Lunar dates and death anniversaries use the Vietnamese lunar calendar (UTC+7) instead of the Chinese one, so dates no longer shift by a day or a month in the years where the two calendars differ. The `lunar-javascript` dependency is removed.

### Fixed

- Sign-in and sign-up errors (wrong password, unconfirmed email, email already registered, weak password, too many attempts) are shown in Vietnamese or English instead of Supabase's raw English text; unknown errors show a generic message.
- Quick search (Ctrl/⌘K) and the person pickers (tree root, kinship, add relationship, export): pressing Enter to finish a word typed with Telex or VNI no longer opens or picks the first result. The member form asks for the month when a day is entered, and older dates with a day but no month show only the year instead of reading like a month.
- Opening a link with `?rootId=` no longer replaces the tree root you chose; the root is remembered only when you pick it in the root selector.
- Signing in with Google or Facebook from a shared member link now opens that page, as password sign-in already did, instead of the dashboard home. Self-hosted apps on a domain other than the Supabase Site URL need `https://<domain>/**` in Redirect URLs (see README).
- A first visit without a saved language now opens in English when the browser prefers English (Vietnamese otherwise); a language picked in the app still wins.
- `.env.example` no longer quotes values, so `docker run --env-file` no longer keeps the quotes in the site name, sender email or app URL (which broke approval emails and the sitemap).
- Member page: parents are listed father first, spouses and children in the same order as the tree (children with the same birth order by birth date); kinship path lines such as "is the husband of …" end with a period and no longer capitalise mid-sentence; the family book title picks a surname when two are equally common (earliest generation, then by name) instead of leaving it empty.
- Administrators now get the approval email when Supabase "Confirm email" is off: it is sent when the new account signs up or signs in with a password, not only after an email confirmation or SSO login. The email is always in the app's default language (Vietnamese) instead of the new user's.
- The gallery accepts phone photos up to 20 MB (GIFs up to 10 MB) and shrinks them before upload, instead of refusing anything over 10 MB; deleting a photo keeps its file while another gallery entry still uses it.
- Tree and mind map PNG/PDF exports no longer show the +/- branch buttons, and multi-page A4/A3 PDFs use portrait pages when that takes fewer sheets (a tall, narrow tree on A3: 9 sheets instead of 13).
- The backup page says more clearly that JSON/CSV/GEDCOM backups hold no profile or gallery photos, nor photo titles and descriptions.
- The lineage book title uses the family's own surname: in-laws are no longer counted, accented names typed in different Unicode forms count as one, and a tie goes to the earliest generation.
- The age card on a member page no longer shows negative ages, and shows the age when only a lunar death date is known.
- The member form refuses two-digit years (85 instead of 1985) and decimal days, months, years, birth orders and generations with a clear message, instead of saving them or showing a database error.
- GEDCOM: a note, name or burial place starting with '@' is exported as '@@' so other programs no longer read it as a pointer, and '@@' in imported files (e.g. 'a@@b.com' from Gramps) becomes '@'.
- Events: a death anniversary more than 365 days away (after a lunar year with a leap month) now shows in the upcoming tabs instead of only under 'Past'.
- Kinship finder: half siblings (same father, different mothers) are ranked by birth year before birth order, so a child born in 1953 no longer calls a 1965-born half brother "Anh trai" when each mother's children are numbered on their own.
- Data check compares birth orders only between children of the same pair of parents, so half siblings numbered per mother are no longer reported as sharing an order or being numbered against their birth dates.
- Kinship finder: a person whose gender is "Other" is no longer called as a man ("Chồng", "Bố", "Anh trai"): terms list both forms ("Vợ/Chồng", "Bố/Mẹ", "Ông/Bà nội", "Anh/Chị", "Chú/Cô", "Con dâu/Con rể"), with a note that the gender is Other; a parent of gender Other leaves Nội or Ngoại open ("Ông nội/ngoại").
- GEDCOM import: estimated dates (`ABT`, `BEF`, `AFT`, `EST`, `CAL`) are no longer taken as exact; the original text goes into the note (`BIRT: ABT 1950`). Foster, step and sealing children (`PEDI FOSTER`/`STEP`/`SEALING`) become adopted children with a note line, instead of biological children.
- GEDCOM import: a person without a name is saved as "Chưa rõ tên" ("Unknown" in English) in the interface language instead of always "Unknown", and the import confirmation says how many such people the file has.
- Merge preview rejects profile IDs that are not UUIDs before querying.
- Members with several spouses: the tree, mind map and family book list the spouses by the spouse's birth year, then by when the marriage was added, so the order no longer looks random. A restore keeps when each relationship was added, so the order survives a backup and restore (migration `20261030120000_restore_relationship_created_at.sql`; older backups restore with the restore time).
- Kinship finder: the new wife of your father is now "Mẹ kế" and the new husband of your mother "Bố dượng", and they call you "Con riêng của chồng" / "Con riêng của vợ" (was "Vợ của Bố" / "Chồng của Mẹ" and "Con").
- Kinship finder: your spouse's aunts, uncles and grandparents are called as your spouse calls them ("Cô", "Ông nội") instead of "Cô vợ" or "Ông nội vợ" ("Cô vợ" means the wife herself); only parents, siblings and cousins keep vợ/chồng ("Bố vợ", "Anh chồng").

- A death anniversary on day 30 of a lunar month no longer disappears in years where that month has 29 days: it falls on day 29.
- A death in a leap month keeps its leap month: the anniversary falls in the leap month in years that have it, otherwise in the regular month.
- CSV import keeps text columns as text: phone numbers keep their leading zero, ids and dates are no longer turned into numbers or dates. Only the number and yes/no columns of `persons.csv` are converted.
- Kinship terms through marriage: no more double spaces ("Em vợ (họ)"), and a younger sibling's husband or wife is "Em rể" / "Em dâu" instead of "Em rể (họ)" / "Em dâu (họ)".
- Restoring a backup no longer leaves the family tree half deleted when something fails: the delete and all inserts run in one database transaction (`restore_backup` function, migration `20261026000000_add_restore_backup.sql`), so on any error the current data stays as it was. Databases that have not run the migration yet keep the old restore and show a reminder to upgrade on `/dashboard/upgrade`.
- Restoring a backup larger than 1 MB (a few thousand members) is no longer rejected by the server: server actions accept up to 25 MB, the limit of the restore file picker.
- Gallery uploads check the size (10 MB), the type (JPG, PNG, GIF, WEBP) and the file's content for both the file picker and drag-and-drop; a renamed non-image file is rejected before anything is uploaded, and the stored file extension follows the real image type instead of the file name.
- GEDCOM export puts each child in the family of its own two parents: a child of a man's second wife is no longer also linked to his first wife, and a child linked only to the father no longer becomes a child of his wife after re-import. A parent with gender "other" and no spouse keeps the link to the children.
- GEDCOM keeps adopted children adopted (`PEDI ADOPTED`) on export and import.
- GEDCOM export writes the first word of a Vietnamese name as the surname (`/Nguyễn/ Văn An`, with `SURN` and `GIVN`); import reads `SURN`/`GIVN` when present, and files from earlier versions still import as before.

### Known issues

- Lunar death dates saved before this change were computed with the Chinese calendar and are not recomputed automatically; in the years where the calendars differ they can be a day or a month off. Admins can review and fix them with the "Recompute lunar death dates" tool. A lunar date typed in by hand (with the solar date derived from it) cannot be told apart, so leave those rows unselected.
- GEDCOM has no date with a day but no month, or without a year: export keeps only the year, or leaves such a date out. Lunar dates stay in the file only as a custom `_LUNAR` tag, which other genealogy programs ignore.
